# 面向顶刊顶会成果产出的 skill 改进要点

日期：2026-11-21（Asia/Shanghai）。依据当前 [research-partner](../research-partner/SKILL.md) 与 [源码调研](../research/skill-survey-2026-11-20/README.md) 提炼。本文是适配总结和改进建议，未修改主 skill，也未启动具体课题。

## 核心定位

在真实证据、可用资源和既有授权内，主动承担从研究判断、方法构造、验证到成稿返修的推进责任，尽可能缩短形成有分量、可核验、可投稿成果的路径，降低用户组织、操作和反复决策成本。顶刊顶会是问题选择、贡献深度与证据质量的目标，不是录用保证。

按成果价值安排工作：**值得投入的问题 → 有实质增量的解法或发现 → 决定性证据 → 完整论文与附件**。复现、资源控制、记录和审计围绕这些环节按需开展。

## 八条适合本 skill 的原则

### 1. 主动承担整体成果推进

用户给定目标和材料后，助手判断当前最大瓶颈，推荐主线，安排依赖并执行。阶段完成后在整体委托内接续必要工作；询问状态、收到新材料或完成一个小任务，都不自动终止整体目标。

每个主要阶段应推进至少一类实质产物：贡献判断、关键推导/实现、可信证据、主稿/附件。文档数量和运行数量不单独代表进展。重要取舍向用户准备具体选项与依据，常规步骤沿已有授权继续。

**当前状态：已覆盖，属于必须持续保持的核心定位。**

### 2. 从“成功后增加什么”倒推选题和投入

主要投入前回答：谁会因结果改变认识或方法选择？最近工作和认真调好的简单方案还缺什么？什么证据才能显示差别？用户已有理论、代码、数据和实验条件能形成什么优势？

问题可以来自机器人控制、具身智能或相邻领域，不把热门模块、可用设备或某篇参考论文当作必选答案。预想成功仍不足以支撑目标贡献时，主动重构问题或解法。问题有潜力但机制未知时，给探索预算并设计下一验证，避免过早按低风险、易实现程度筛掉有价值方向。

**当前状态：已有贡献预判；重点是把判断落实为选题推荐、资源分配和方案修正。**

### 3. 主动把研究瓶颈转成可实现的机制

对有价值但缺成熟方案的问题，提出有区别的解释和解法，比较使用的信息、作用环节、核心假设、最强替代及验证成本。跨领域借鉴须检查适用假设；每个组件说清产生什么、由谁使用、为何需要。

昂贵实现前可用推导、数据流走查、解析算例或小原型暴露未定义量、循环依赖、无效组件和无效对照。失败诊断从能工作的较简单版本出发，逐步恢复条件，定位首个失效来源。区分实现失败、机制未成立、测量不足及方向被反证，依据证据继续修正或转向。

**可借鉴：Evo experiment-craft、TheSyBuilder 的机制审计。当前已要求方法设计，新增价值是具体诊断方式。**

### 4. 优先取得能改变研究决定的证据

每项主要实验对应一个主张或竞争解释，并说明不同结果分别会使我们继续、修改、收窄或停止什么。先验证可能推翻主要投入的未知，再扩大训练、采集或系统实现。

比较相关强方法与认真调好的简单基线，核对信息、数据、算力、调参和人工投入。为问题选择适合的证据：机制、理论、系统能力、效率、可靠性或有意义的负结果，不把指标上涨等同于机制成立。小规模验证只支持其覆盖条件；重要问题若需要更大投入，应明确成本与理由，不能因为某个小测试便宜就让它替代决定性证据。

**当前状态：已覆盖；应保持为实验排序的主要依据。**

### 5. 将有希望的结果转为可靠的论文证据

筛选中领先的候选先保留为候选。需要晋升为后续比较参照或论文关键结果时，按噪声、独立单位、效应意义和预算安排新的确认运行；确认汇总与因领先而入选的筛选运行分开。记录已看过的数据和修改的判据，不设置通用种子数或固定百分比门槛。

核对运行结束、证据完整、任务验收和结果复现分别是否成立。长任务恢复先检查同一任务身份和输出，避免重复运行。软件资源限制在安全短测试中验证其生效范围及终态记录；检查器通过只支持它实际检查的内容。

**可借鉴：ray-caster、gevolve、RigorPilot、science-superpowers。这些属于值得补充的执行细节。**

### 6. 让研究发现及时进入同一份主稿

有可信主线就写已有依据的问题设定、文献定位、方法和协议；缺结果处明确未完成。真实结果得到后同步生成图表、图注和结果分析，回查摘要、引言贡献与结论，修正证据不支持的表述。

每个主要段落推进一个论点，每张图回答一个研究问题；方法组件连接上游瓶颈和下游证据。重要数字关联原始位置、运行/配置、聚合或变换、单位/分母及呈现位置；来源更新后核对受影响图文。按需比较论文与代码激活路径、生效配置及实际运行条件，解决语义漂移。

**可借鉴：UCL、PaperSpine、scientific-paper-skill、Norman 的段落论证。当前已有研究写作同步，重点补来源到呈现位置和生效配置的核对。**

### 7. 提前处理最可能使贡献不成立的质疑

按目标读者和贡献类型寻找最有杀伤力的反对意见：问题不重要、近邻工作已覆盖、简单方案解释收益、比较不公平、机制证据不足或结论范围过大。把意见转成具体修复、最小补实验或有证据的异议，完成后回写稿件。

审查意见本身也要核对原文、上下文、来源和PDF抽取；不成立的意见撤销或降为待核实。实际独立审查须如实记录执行情况。无论来自单模型、多角色或多个模型，意见数量和多数票都不能替代证据。

**可借鉴：UCL/ARIS 的证据化审查、shack 的审稿意见复核。现有 skill 已有视角与修复要求，可补明确的误报处理。**

### 8. 主动收敛到成品，减少用户负担

进入成稿期后，明确目标投稿所需的贡献、证据、主稿、图表和附件缺口，区分必要工作与可选增强。关键证据足够时持续完成成品；出现实质新反证时再修订路线。用户劳动、现场复位、采集、排队和等待计入成本；现场操作前由助手备好脚本、步骤、记录与判据。

复用唯一项目状态入口，保存真实结果、决定、适用条件、重开理由和下一可执行动作。恢复时接着已有证据推进。交付同时说明研究有效性、目标竞争力和提交完整性各自的依据及剩余缺口。

**当前状态：已覆盖，是防止研究长期停留在探索和建议阶段的关键行为。**

## 适合写进 skill 的优先顺序

| 层次 | 要求 | 后续维护方式 |
|---|---|---|
| 最高优先：研究与成果责任 | 主动统筹、贡献预判、形成机制、取得决定性证据、完成稿件 | 已有核心要求，保留简洁表达，用真实任务与行为评测检验是否落实 |
| 直接补强：执行细节 | 候选确认后晋升、桥接失败条件、状态分层、数字传播、生效配置与审稿误报核对 | 合并进已有 references，不另加总流程或全局审批 |
| 按需支持：工具与管理 | 远端证据交接、专用检索/统计/作图工具、资源控制器 | 具体任务需要时调用，复用已有记录和产物 |

不将每阶段停等批准、固定实验数量、强制多代理/某模型/后台机制、庞大文件体系或回避不利结果的写作规则写入通用 skill。用户已有授权和真实任务需要决定执行边界。

## 后续评测要同时验证“能推进”与“不会误判”

此前迁移方案已提出8个细节评测。为了检验成果推进能力，还应重点看以下情形；这些是拟议评测，尚未执行：

| 情形 | 应观察到的成果行为 | 主要失败表现 |
|---|---|---|
| 只有宽泛方向、已有材料和资源约束 | 识别可用积累，形成有依据的候选与主推方向，执行授权内能决定下一步的工作 | 把选题、任务拆分和下一步全部退回用户，或只列热门话题 |
| 问题值得做但方法不成熟 | 提出机制上有区别的解法，推进关键推导/原型，明确比较与判别条件 | 只指出创新不足、只换术语或堆通用模块 |
| 简单强基线已解释方法收益 | 如实修正原主张，在预算内检查剩余有价值的未知，并推荐重构或转向 | 隐瞒对手；继续包装；或以一条路线失败为由结束整体委托 |
| 初步结果反复不稳定 | 区分实现、测量、机制和精度问题，用有预算的诊断或确认推动决定 | 无目的扫参数、只挑好种子，或把未知直接判为无价值 |
| 核心证据已足够、要求完整论文 | 对照目标缺口持续写同一主稿，补必要附件并检查实际输出 | 继续无关扩展、重复大纲、只交报告而没有完成稿件 |
| 研究中用户询问状态或提供新材料 | 简要回应并将新信息接入原目标，继续未完成的关键工作 | 将状态答复当整体终点，或重新启动整套问答/调研 |

已有原则是否生效，应看它是否改变了真实研究决定、补齐了关键实现/证据、增加了可审阅稿件，而不是只核对提示词是否出现某些词。
