# 状态、接续与多篇论文

## 一个项目一个状态入口

持续委托时复用已有项目总览、研究状态与产物目录；按项目入口的链接定位背景和状态，不因为它们在子目录就另建副本。没有约定时才在项目根创建一个符合项目语言的“研究状态”文档，并从总览链接它。个人背景与通用 skill 分开，未知或过期资源在影响决策时核实；不自动修改个人档案。

从用户指定材料和本项目资产主动提取能形成差异的积累：已掌握的问题、可信结果、代码与数据、独有观察或可用实验条件；记录来源、真实状态及它们能缩短哪条成果路径。只在缺失信息会改变路线选择时补问，不要求用户先整理长问卷。已有积累影响候选优先级，但不能把设备便利当成问题重要性，也不把可能优势写成已证实的新颖性。

状态应足够下次直接行动，可按需使用：

```markdown
# 研究状态
- 更新日期、当前用户目标及范围：
- 协作约定与决策边界：助手可自主推进的范围；确需用户提供或决定的事项
- 所处阶段与本轮交付：相对上一主要阶段，贡献判断 / 关键实现 / 必要证据 / 主稿的实质变化
- 研究问题、贡献类型、主目标与备选：用户确认 / 助手暂定
- 可形成差异的已有积累：来源、真实状态，以及能缩短的成果路径
- 核心主张与证据表位置：支持 / 不支持 / 未知；适用条件
- 资源与预算：已核实 / 用户提供 / 未知；已授权范围、本次探索上限、实际消耗及用户投入
- 产物入口：文献、协议、代码、run、图表、稿件及各自真实状态
- 研究有效性 / 目标竞争力 / 提交完整性：依据与缺口
- 最近决定：继续 / 修订 / 暂停 / 停止；证据、适用条件、重开原因或重启条件
- 本稿范围与剩余工作：投稿必需项及完成条件 / 可选增强；探索期标为暂定
- 阻塞与下一步：最影响贡献或成稿的依赖、动作、责任人、产物与结果分支
```

计划、已尝试、运行中、已完成和失败要区分；文件存在不代表完成，下载不代表读过，脚本存在不代表运行过。预期结果保存在规划材料，不得被状态摘要提升为实测发现。保留失败与反例，过时方案标注已取代并链接新版本。

恢复时先核对最新用户说明、状态、关键产物和时效；被新请求取代的历史暂停不能继续阻止工作。若状态与日志/文件冲突，以可核验证据纠正并说明；无实质变化则复用已解决判断，直接推进剩余依赖，不从头调研或要求用户重选方向。重开条件沿用 [研究推进流程](研究推进流程.md)。记录只服务接续，不为每个小动作生成重复日志。

## 多篇论文的安排

按重要性、完成路径、资源冲突、竞争时效与用户投入选择当前主项目。通常集中完成一条主线，同时保留有意义的备选；数量服从并行能力，不把在研项目数当产出。理论、方法、系统、数据或实证贡献可以共享基础设施，但每篇必须有独立完整问题与证据，交叉引用并避免不当拆分和重复发表。

优先识别共用设备、采集时间和关键假设的项目；若共用假设可能同时失败，说明相关风险。价值相近时，补齐已有可信结果项目的必要证据与稿件通常比另起炉灶更快；主张已被否定时不要因沉没成本继续投入。

时间规划围绕依赖与交付：最近可完成的判别试验、下一项核心证据、完整初稿和投稿准备；估算与投入上限沿用 [研究推进流程](研究推进流程.md)，计入共用资源排队及用户现场劳动。优先利用已经取得的结果完成正文和分析，不以增加在研项目抵消主项目停滞。

## 接续交接

每次主要阶段结束保留实际发现、与计划的差异、决策理由及下一步入口。交接只给必要材料：读什么、运行什么、看哪些输出、何时继续/停止。用户不应在文献、实验和写作之间反复重新整理上下文。

持续委托下，下一步由助手依据状态主动选择并执行；用户发来新材料或说“继续”即可接续，无需重新说明流程。待用户事项要写清需要什么、助手的推荐、影响哪个后续动作；同时保留助手可继续完成的工作，避免整个项目因一个局部阻塞停滞。

本 skill 不会自行建立后台任务、持续监控或跨会话隐式记忆；需要定时工作时按用户明确请求及环境能力另行处理。用户只问局部问题或要求记录时完成该范围，不自动扩展项目。
