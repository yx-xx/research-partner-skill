# 历次绘图结果与问题复盘

日期：2026-11-17。依据已生成的 0.1 / 0.2 / 0.3 图片和验证记录重新检查。本次整理结果，不修改引擎或重新制定开发计划。

## 总体判断

当前实现确实有一部分复杂化：文件协议、候选搜索、评价和修复闭环已经比较多，但“把基本素材画得像、线条干净、部件好编辑”尚未稳定达到。工程能力的增长快于实际绘图质量的增长。

已实际具备：生成真实 SVG 路径、分组、文字；按 ID 改色、移动和导出；部分简单形状及细线重建。尚未实际证明：面对不同科研素材，能稳定生成结构完整、线条简洁、科学部件分明的高质量复刻。

测试通过、机械指标提高和文件可编辑都不能代替成品质量。下面同时记录成功、失败和退步。

## 1. 自建椭圆、有机轮廓、孔洞和锐角

结果：简单椭圆、有机闭合轮廓和孔洞可以转成曲线路径；简单直线可恢复成描边。受测锐角案例需要回退到折线才能保住形状。

问题：

- 输入是专门构造的简单几何，不能证明复杂插画也能恢复。
- 保住锐角与获得平滑曲线之间仍有取舍；回退后不一定具有干净、简洁的设计感。
- 几何检查只证明部分边界没有明显损坏，不证明识别出了正确的科学对象。

判断：基础几何工具可用，不能据此宣布完成通用科研绘图。

对照：[通用几何](../outputs/general/overview.png)。

## 2. 架构图局部（0.1）

结果：生成了 28 个对象，包含框、文字、箭头及局部图标；能够编辑。

问题：

- 是宿主给定布局和转写文字后的简化重画，不能称为自动恢复整张架构图。
- 对照中有标签、箭头和右侧可见内容未完整重现。
- 文字位置、字号、框的比例和连线形态与源图有差异。
- 阴影、背景线路和装饰没有复刻。装饰可以有意简化，但应先明确目标，并保证信息结构完整。

判断：证明可以拼出可编辑示意图；没有完成原图的完整复刻。

对照：[架构局部](../outputs/prototype/architecture/comparison.png)。

## 3. 头像图标（0.1 → 0.3）

结果：0.1 使用明确调色板的辅助版本，圆形和人物轮廓相对完整，但边缘粗糙、渐变丢失。0.2 / 0.3 自动版本依然未通过质量验收。

问题：

- 自动版本把本来简单的圆形和人物切成碎块，头部和身体出现破碎、缺口。
- 背景、图标边框和抗锯齿像素混入颜色分区。
- 颜色更接近的另一候选反而丢失更多内部边界，最终未替换旧候选。
- 后来的自动处理复杂度增加，却没有超过早期辅助版本的实际效果。
- 这种简单图标仍未稳定画好，说明整体按像素分区没有充分利用其明显的几何组成。

判断：不合格。这是复杂度增加但实际收益不足的直接例子。

对照：[0.1 辅助版本](../outputs/prototype/avatar/comparison.png)、[当前自动版本](../outputs/internal-v03-delivery/user-avatar/comparison.png)。

## 4. 柠檬扁平图标（0.2 → 0.3）

结果：黄色主体和绿色叶片基本恢复，机械检查通过；0.3 保持了 0.2 的结果。

问题：

- 果实外轮廓仍有栅格台阶，曲线不够干净。
- 叶片和叶柄轮廓有偏差，部分接缝存在黄边/颜色混合。
- 画得更接近后，路径段数由早期基线的 234 增至 309；外观改善没有同时换来更简洁的路径。
- 颜色层可以编辑，但没有自动证明已按果实、叶片、叶柄等用户想编辑的部件组织好。

判断：达到粗略矢量化，尚未达到干净的图标重绘质量。机械 passed 不应被称为高质量复刻。

对照：[柠檬](../outputs/internal-v03-delivery/twemoji-lemon/comparison.png)。

## 5. 烧瓶黑白图标（0.2 → 0.3）

结果：主体和内部白色区域保留，机械检查通过；0.3 未带来进一步改善。

问题：

- 瓶口、肩部和底部圆角与源图不同，部分圆滑部位变成折角。
- 斜边仍有台阶，不能只因轮廓重合较高就忽略线条质量。
- 作为一个简单黑白形状，路径表达还不够简洁，仍保留了栅格采样特征。

判断：形状基本像，线条质量不够好；未达到原图的圆滑程度。

对照：[烧瓶](../outputs/internal-v03-delivery/fontawesome-flask/comparison.png)。

## 6. 生物素材局部（0.1 → 0.2 → 0.3）

### 0.1：主体可见，内部大量遗漏

结果：橙色外围、紫色中心和部分暗线可见，中心几何包含宿主辅助构造。

问题：原图有多层连续褶皱，结果把大量结构合并成橙色大块，内部暗线大量丢失；渐变、细节和层次不足。看起来像一个示意近似，但不是完整复刻。

对照：[0.1 生物局部](../outputs/prototype/nucleus/comparison.png)。

### 0.2：自动结果严重退化

结果：最终选中的结果几乎是整块粉色，内部结构基本消失。

问题：

- 源局部的整体占据接近矩形，整体轮廓 IoU 可以达到 1.0，却完全没有恢复内部内容。
- 颜色层候选复杂且不合格；当时按失败原因数量挑 best effort，让更空的单色候选胜出。
- 加入了多候选和评价机制，却仍输出比早期辅助结果更差的图。这是实际退步。

判断：明显失败，不能用轮廓指标解释为“基本成功”。

### 0.3：大部分可见线带补回，但仍未完成

结果：外围折叠带、中央紫色区域和很多内部暗边重新出现。颜色误差由 0.195633 降到 0.057242，可见内部对比边界覆盖由 0 提高到约 90.5%。

仍有问题：

- 部分细线、薄带和色彩分区仍缺失或合并。
- 渐变、高光、体积感被少量平面颜色代替，整体仍有块状感。
- 原图的黑色标注引线也被画入，没有自动与科学结构分开。
- 当前主要是 6 个绘制色层，不等于已按科学部件完成分解；用户要单独编辑某条褶皱时，未必已有对应对象。
- 路径仍有 3263 段，超过原 2400 段预算。放进少量复合路径没有消除边界复杂度。
- 后续静态审计纠正：默认工程记录的分支超预算发生在 analysis 的骨架摘要，不能据此说实际尝试并拒绝了一个中心线绘制候选。该默认工程的绘制候选没有 stroke_layers。这张图的改善主要来自面域表示，不能宣传为复杂中心线已恢复成功。
- 90.5% 是图像对比边界覆盖，不是科学结构完整率。

判断：相对 0.2 明显改善，但仍不合格，保持 needs_review。

对照：[当前生物局部](../outputs/internal-v03-delivery/user-biological/comparison.png)。

## 7. 一像素细线、弯曲线和分支夹具（0.3）

结果：旧版会消失的一像素线得到保留；中心线路径能实际改色、改线宽、移动和独立导出。

问题：

- 这是独立绘制的简单故障夹具，证明修复了特定算法问题，不代表真实生物图已完成同样恢复。
- 保留像素面积可以避免断线，但可能同时保留台阶感；“不丢线”与“线条好看”是两项要求。
- 暗线提取不能自动理解线条角色，也不能覆盖亮线、纹理密集或复杂交叉。

判断：这部分实现有明确收益，但适用范围有限。

对照：[一像素细线](../outputs/internal-v03-delivery/one-pixel-details/comparison.png)、[中心线候选](../outputs/internal-v03-delivery/centerlines/comparison.png)。

## 共同问题与复杂度反思

1. **像素分区承担了过多的对象重建工作。** 同色不一定是同一部件，不同颜色也可能只是一个部件的明暗。当前绘制层与用户想编辑的对象仍有距离。
2. **线条质量还没有稳定做好。** 简单图标都能看见台阶、折角、接缝与形变；复杂结构中则容易在“丢细节”和“保留大量节点”之间摆动。
3. **评价机制比成品成熟得更快。** 能报告遗漏、拒绝、回滚值得保留，但发现问题不等于修好了图。通过检查也不等于美观或科学正确。
4. **多候选的收益不稳定。** 它帮助生物局部从单色块恢复出内容，但没有让头像稳定变好，也没有让柠檬和烧瓶进一步变干净。
5. **自动程度与人工辅助应讲清楚。** 架构布局、文字转写和早期中心几何有明确宿主辅助，不能和只给粗区域的自动结果混为一谈。
6. **复杂科学素材的独立编辑仍不足。** 有 SVG 和颜色组，只说明几何可以编辑，不能证明用户关心的每个部件都能方便地单独修改。
7. **验证范围太窄。** 两个公开开发输入和少量已见截图，不足以证明跨风格能力；测试数量增长没有补足这项证据。

此外，先前 overview 三列显示尺寸不一致，不适合直接比较缩放后的粗细或大小。本文链接的各个 comparison.png 使用同一源区域对照，更适合检查实际缺陷。

当前实际状态是：文件生成、基础编辑和部分几何处理可用；简单素材有粗略复刻能力，但稳定、干净、部件清晰的科研素材重绘尚未做好。现阶段确实不应把框架复杂度或测试数量当成绘图能力的主要成果。
