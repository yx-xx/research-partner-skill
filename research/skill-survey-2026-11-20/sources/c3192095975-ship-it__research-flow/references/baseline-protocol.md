# ResearchFlow Baseline Protocol

当用户没有安装任何适用的科研 skill，或宿主完全不提供 skill 清单/文件系统访问时，使用本基线流程。它不假装拥有专用工具，但保证科研工作仍然有结构、证据和质量门。

## 1. 适用范围

触发条件：

- 没有 `scope`、`search`、`reading`、`analysis`、`figures`、`writing`、`review` 等可用能力；
- 发现脚本不可运行；
- 宿主只提供空白 skill 清单；
- 用户明确要求不加载任何专业 skill；
- skill 依赖的 MCP、API、浏览器或凭据不可用。

## 2. 通用阶段

| 阶段 | 基线动作 | 最低产物 |
|---|---|---|
| 0 立项 | 写研究 brief：问题、目标、约束、成功/失败标准 | `research-brief.md` |
| 1 定向 | 列出候选假设、否证条件、竞争解释 | `hypotheses.md` |
| 2 检索 | 记录数据库、查询式、日期、命中和排除项 | `search-log.csv` |
| 3 精读 | 对每个关键来源记录页码/章节、原文、解释 | `evidence-ledger.csv` |
| 4 证据 | 建立 claim-evidence 矩阵，标记未核验 | `claim-evidence.csv` |
| 5 分析 | 保存原始数据、清洗数据、代码、命令和环境 | `data-manifest.yaml` |
| 6 统计 | 检查实验单位、重复、效应量、不确定性和检验 | `stats-audit.md` |
| 7 图表 | 每个 panel 写明问题、数据、统计和 source data | `figure-plan.md` |
| 8 写作 | 使用“主张→证据→限制”结构，不补造缺失内容 | 草稿 |
| 9 生产 | 检查引用、图注、编号、格式和包一致性 | 构建产物 |
| 10 评审 | 按结构化清单逐条评审，保留作者确认项 | `review-report.md` |
| 11 回复 | 评论跟踪表 + 修改位置表 | `response-tracker.csv` |
| 12 交付 | 说明格式限制和未执行的外部检查 | 最终文件 + 交付说明 |

## 3. 基线搜索

没有专用检索 skill 时：

1. 明确检索问题和边界；
2. 至少使用宿主可用的搜索工具；
3. 记录数据库/搜索引擎、查询式、日期和结果数；
4. 去重并记录纳入/排除标准；
5. 不把搜索摘要当作全文证据；
6. 关键主张必须回到原始来源或标记未核验。

## 4. 基线精读

每个来源至少记录：

```text
source_id | 作者/年份 | 研究问题 | 方法 | 关键结果 | 限制 | 页码/章节 | 可信状态
```

作者原话和你的解释必须分开。没有页码或章节定位时，标记 `locator_missing`。

## 5. 基线分析与统计

- 原始数据与派生数据分开；
- 保存运行命令和环境；
- 明确独立实验单位；
- 技术重复不能当作独立样本；
- 优先报告效应量、不确定性和样本量；
- 不把统计不显著写成“没有效果”；
- 不把相关写成因果。

## 6. 基线图表

- 先写科学问题，再选图型；
- 每个 panel 对应一个 claim 或分析；
- 保存 source data；
- 误差棒、样本量和统计方法可追溯；
- 颜色不是唯一编码；
- 图和正文数字一致。

## 7. 基线写作

每个核心段落至少回答：

```text
主张是什么？
证据是什么？
证据边界是什么？
还有什么替代解释？
```

不得编造引用、数据、实验结果、作者贡献、伦理审批或数据可用性。

## 8. 基线与能力降级

在 handoff 中标记：

```yaml
catalog_source: baseline
degraded_roles:
  - search
  - figures
  - writing
```

降级不是失败，而是明确告诉用户哪些外部能力未被验证。
