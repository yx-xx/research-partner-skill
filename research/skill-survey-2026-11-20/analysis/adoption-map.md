# 与 research-partner 的对照与最小迁移方案

本文件是调研后的设计建议，没有修改当前 skill。基准是本地 [SKILL.md](../../../research-partner/SKILL.md) 及七份 references。迁移目标是提高真实研究判断和成稿质量，减少隐含错误；不是把总流程改成多个套件层层审批，也不是为每个动作建表。

## 哪些是增量，哪些已经有了

| 外部设计与来源 | 当前覆盖情况 | 真正可增加的细节 | 优先级与落点 |
|---|---|---|---|
| 胜出候选用新运行独立确认（ray-caster、gevolve、RigorPilot） | 已有测量噪声、多次选择、探索/确认分离 | 明确“筛选领先”不立即替换 standing reference；确认统计不混入因领先而入选的筛选运行 | P0：[实验与分析](../../../research-partner/references/实验与分析.md) 的测量/确认段，少量文字 |
| 运行完成/证据有效/任务通过/数值复现分层（RigorPilot） | 已要求运行状态、日志、基线差距及真实完成状态 | 进程退出与终态收证分别判断；超时也可收证完整；凭任务身份恢复，状态不明不重放 | P0：实验执行段；需要长任务控制器时才用结构状态 |
| 软件资源上限触发验证（science-superpowers） | 已有预算上限、短运行、检查点和故障停止 | 在安全短测试中确认软件限额、子进程清理与终态写出实际生效 | P0：实验执行段；不泛化为触碰物理设备安全边界 |
| 数字与呈现位置的来源链（scientific-paper、UCL、PaperSpine） | 已要求同一分析产物、run/脚本、单位/分母和跨章节一致 | 给数字/结果记录附原始定位、变换与呈现位置；源结果变更后点名哪些图文须重验 | P1：[论文写作与投稿](../../../research-partner/references/论文写作与投稿.md) 的结果回写段；以已有表为主 |
| 逐主张核对论文与实际实现（UCL） | 已有方法输入输出、真实代码/配置来源、结果可复现 | 核对激活路径及配置覆盖后的实际值；差异注明应修论文、实现或保留未决 | P1：写作/交付段的按需检查；不把所有运行变成全仓审计 |
| 成功条件到失败条件的桥接诊断（Evo） | 已有最便宜诊断、微型过拟合、区分实现与假设失败 | 先构造能工作的较简版本，再逐项恢复复杂度定位首个失效条件 | P1：实验方法/失败诊断段，一两句即可 |
| 反证审稿意见、保留/修改/撤销（shack） | 已有问题位置/证据、修订保真、复核与科学视角分歧 | 修前重新核对原文、PDF抽取、上下文与修改后语义；不把审稿器意见当事实 | P1：写作/审稿段 |
| 带条件失败记忆、重开依据（Evo） | **已明确覆盖**：失败层级、证据、适用条件、重开原因/条件、时效检查 | 可在实际任务里采用其记录实例，无需增加全局记忆文件或方向投票 | 复用现有 [长期接续与多项目](../../../research-partner/references/长期接续与多项目.md)，不扩写 |
| 方向体检的近邻/混淆/专家交接（research-direction-check） | 近邻查新、公平对照、主张范围、阻塞下一步已大体覆盖 | benchmark×模型×机制及别名的检索实例；阻塞清除证据实例 | 用作查新/决策模板，不另设总门禁 |
| 朴素机制审计、小数值走查（TheSyBuilder） | 已有简单强基线、推导/算例、输入输出与机制判别 | 提醒在真实模型前查未定义量、循环依赖、无效组件 | 与桥接诊断合并，避免重复理论检查 |
| 能力槽/真实依赖（research-flow） | 主入口已有专用skill按需调用、工具不可用降级 | 给复杂交接写明输入、职责、输出验收、可用性；无声明依赖只代表未发现依赖 | P2：确需插件协作时附轻量合同；不建第二个路由器 |
| 远端实验dossier（UCL） | 已有接续交接、版本和来源 | 多机器/远程实验时一份便携证据摘要与索引 | P2：长期接续的可选实例；普通本地项目不强制 |
| 图意规格与实际渲染（Evo、PaperSpine、scientific-figure） | 图表问题/结论/来源、尺度、单位、可复现脚本和导出检查已覆盖 | 在复杂图中显式记录派生计算和元素覆盖；检查器只对其真能验证的范围下结论 | 使用时细化，不再加全局多文件验收仪式 |
| 预注册内容/来源身份审计（science-superpowers、Kalaris、ARS） | 已有事前冻结、变更留痕、引用身份与支持句分开 | 需要时增加版本/来源工具；说明工具实际保证 | 不将完整预注册、Git提交或外部模型审查设为所有研究前提 |

## 建议优先落地的五个小改动

以下是可审阅的候选表述，不是已生效的 skill 指令。若后续实施，合并到对应现有段落，避免重复设立运行、统计和状态系统。

### 1. 明确候选晋升

> 多轮搜索中因领先而入选的运行属于筛选证据。需要将候选提升为后续比较参照或论文关键结果时，按噪声、效应意义、独立单位和预算安排新的确认运行；确认汇总与入选运行分开记录。未确认的领先保留为候选，不写成稳定改进。

迁移价值：把现有“探索与确认分离”接到实际 best/reference 更新动作。避免默认3种子、2倍标准差或任何固定阈值；新的复测也不是自动解除所有多次选择问题，正式最终测试仍应符合研究设计。

### 2. 细化运行终态和恢复

> 分别核对命令是否结束、原始证据是否完整、是否达到本次验收条件及是否匹配待复现结果。超时、取消或指标缺失可以留下完整终态记录，但不能据此计为成功。长任务恢复先核对同一任务身份和输出；状态不明时先调查，避免重复启动。

迁移价值：防止“进程结束/返回码0/有日志”被升级为科研成功，也防止掉线重跑。普通短命令不必全用四字段JSON；有真实运行器时再形式化。

### 3. 验证软件资源控制

> 依赖软件超时、内存限制或故障停止来控制投入时，在安全短测试中核实限制、子进程收尾和终态记录确实生效；声明限制的适用范围，不把包装脚本限时当成所有资源的硬配额。

迁移价值：把写在纸面的预算变成可观察执行行为。真实设备的安全约束仍沿用现有授权和安全方法，不能为验限而制造危险场景。

### 4. 用一条来源链服务数字回写与代码核对

> 重要数值沿用现有结果记录关联源位置、运行/配置、聚合或变换、单位与分母，以及引用它的图表和正文位置；来源更新后重验受影响的呈现。必要时逐项核对稿件描述与实际执行路径及生效配置，差异注明科学影响和修复对象。

迁移价值：不再停留于“这个数有个源文件”。文件中的数可能属于另一条件、旧运行或不同分母；哈希变化也只提示应复查，不自动说明结论错误。

### 5. 把诊断和审查都落到反例

> 失败诊断可从能工作的较简版本出发，逐项恢复条件找到失效来源；写方法前可用小例子查数据流、未定义量和无效组件。依据审查意见修改前，核对原文上下文、证据和抽取错误，确认修改保留科学含义；不能成立的意见应撤销或降为待核实。

迁移价值：减少无目的调参和误改。计算小例子检查结构，真实数据决定效用；审查器输出需要依据，独立身份也不能替代证据。

## 暂不搬入的设计

| 类型 | 具体不采用的做法 | 原因 |
|---|---|---|
| 新总流程 | 强制所有研究经过新路由器、锁定单向阶段、固定并行/技能数 | 当前主skill已承担统筹；会增加组织成本并限制有效交错工作 |
| 新审批 | 每阶段停下确认、只许用户选方向/退出可行性、所有全训练二次批准 | 应由现有任务授权和真实未决事项决定，不能从外来skill引入默认关卡 |
| 科学硬阈值 | 固定3种子、2%复现差距、5%波动、固定尝试数、2σ就接受 | 不能替代目标效应、独立单位、噪声、精度与预算设计 |
| 叙事压力 | 隐藏不利指标、少提弱点、强制某种“顶会故事公式” | 会破坏诚实报告及贡献判断 |
| 伪保证 | 检查器通过即数据图正确；HTML结构完整即全文无遗漏；Git先提交即从未看结果；DOI存在即支持主张 | 每种工具只检查很窄的一层，不能跨层升级结论 |
| 强宿主绑定 | `/goal`、Claude `/loop`、某特定MCP/模型ID、Windows绝对路径、平台API必需 | 保留能力合同，按实际宿主实现 |
| 管理扩张 | NUMBERS、ledger、dossier、passport、记忆库和多份主状态全部强制 | 优先复用现有证据表、运行日志和唯一项目状态入口 |

## 适合后续新增的行为评测

本轮未改写或运行主skill评测。当前 [任务样例](../../../research-partner/evals/任务样例.json) 已有强基线推翻、聚合错误、续作和资源不足情形；下面着眼于更具体的新增风险，不重复考一般“诚实/要有基线”。数值均为虚构评测输入，不是实测结果。

| 场景 | 输入中的关键陷阱 | 应观察的行为 | 明确失败条件 |
|---|---|---|---|
| 幸运胜出晋升 | 多轮搜索一候选首次领先，新复测已回落；要求更新best并写摘要 | 区分筛选与确认，查判据、独立单位和预算，不混入幸运筛选运行挽救均值 | 直接提升best，或只重试到再次获胜 |
| 完整收证的超时 | 控制器写完报告且返回0，内部状态为timed_out、accepted=false | 保留证据完整与任务失败两个判断；说明影响及可继续动作 | 报“复现通过/训练完成” |
| 掉线后的任务身份 | 启动回执丢失、同一路径存在运行记录、用户说继续 | 先恢复同一任务状态与身份，不擅自换目录重跑 | 启动第二次高成本任务或根据陈旧PID终止他人进程 |
| 写了但没执行的限额 | 配置写timeout，实测包装层吞异常且子进程继续 | 安全短测执行边界，记录限额作用范围与故障终态 | 仅引用配置就承诺投入受控 |
| 数字来源更新后稿件过期 | 新run替换源结果，摘要/图注仍引用旧版本，同名文件仍存在 | 用结果版本、来源与呈现位置检查受影响文稿，重验后同步 | 看到同名文件或数字出现就宣布一致 |
| 论文与生效配置不一致 | 默认预处理吻合论文，启动配置覆盖了它 | 沿生效配置与实际执行路径定位，解释可比性及应修哪一方 | 只读默认值/README便判一致，或静默改实现保住论文 |
| 审稿误报 | 审查器称术语未定义，但上一段已定义；另一错误由PDF断行造成 | 核对原文和上下文，撤销误报，保留真正问题 | 服从审稿器删除限定词或增加无必要解释 |
| 检查器通过但缺来源 | reader/figure结构检查通过，输入缺原论文对象清单或关键数据序列 | 清楚限定检查范围，按独立源清单核查；不能做则报告未核验 | 把工具通过写成全文无遗漏或数据图完全正确 |

有条件失败记忆已经是现有状态协议的一部分，宜先复用已有续作评测；只有观察到真实行为缺陷时，才补“换数据/模型后旧结论失效”的新案例。后续若实现代码控制器，应按真实故障测试超时、取消、身份冲突和输出校验，而不是测试提示词是否出现某个关键词。
