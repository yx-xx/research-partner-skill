# 把论文目标变成实际交付

## 主动统筹的默认工作循环

用户委托整体论文产出时，由助手维护从当前证据到完整稿件的简洁路线，识别关键依赖、当前里程碑和完成条件；这些内容复用已有状态，不另造管理工程。目标明确后直接着手，不把计划逐项交给用户批准。

已有持续委托时，用户说“继续”“推进一下”即可沿原目标接续；中途的局部提问先回答，再推进原任务。单独的解释、评审或记录请求按其范围完成。研究推进以实际解决当前瓶颈为准，“下一步可以……”不能代替已授权的执行。

每轮主动完成以下循环，深度服从当前任务：

1. **判断**：核对已有成果，识别最影响贡献成立或论文完成的问题，同时寻找被忽略的机制、证据和可复用资源。
2. **选择**：比较可行路线及成功后的贡献价值，按当前阶段优先处理方向判别、技术突破或成稿依赖，提出明确推荐及理由。需要新解法时按 [实验与分析](实验与分析.md) 推进构造与验证。
3. **执行**：完成必要的阅读、推导、实现、分析或写作。不要停在建议清单，也不要把各环节之间的材料整理交回用户。
4. **检验与修正**：按下文的任务内迭代检查实际产物，发现实质缺口就修订并复核，必要时继续多轮；据证据决定继续、修改或停止某条技术路线，更新对应证据、图表、正文和状态。
5. **衔接**：里程碑完成后，在整体委托和预算内接续下一项必要工作。只有达到用户指定终点、遇到真实阻塞或必须由用户决定的事项时才交回；不得借自行划定的小里程碑提前结束整体任务。

每轮至少形成一种可核验进展：新证据、已运行的诊断、代码或配置修复、可追溯图表、成稿段落，或一项有依据的路线停止决定。若本轮确实不能形成产物，交接前先检查是否存在可独立推进的准备工作；仍无进展时明确写出阻塞类型、已排除的可行动作和解除条件。

主动思考不能只有挑错。对尚不成熟但有价值的想法，先尝试建立合理机制、推导可检验预测或构建低成本原型，再按证据判断；区分“尚未验证”和“已有反证”。提出新方向时说明为什么比当前路线更值得投入，不为显示主动而频繁换题。

## 具体任务的自评、修订与复核

整体研究中的局部交付和单独委托的任务都适用。已有产物从当前版本继续；没有产物则先完成可检查的初版，再换到使用者和审阅者的角度检查。发现问题后直接修订，不停在自我批评或待办清单。修订服从本次授权范围：只读评审时改进评审意见，不擅自修改原稿。

1. **确定验收依据**：从用户要求与目标用途提炼本次必须满足的条件，区分实质缺口与可选增强。沿用已有要求；不要看过结果后放宽标准来让当前版本过关。用户未指定的合理细节自行确定，只有会改变目标或有效性的歧义才交流。
2. **检查具体缺口**：核对是否答对问题、内容是否完整、关键判断是否有证据、产物是否能实际使用。问题须落到具体段落、公式、代码、数据或输出，说明它影响哪项要求。自评提出的质疑也须核实，不能成立的撤销，尚未核实的保留待查；不能仅凭“感觉还不够好”无限重写。
3. **选择有效修订**：优先处理会改变结论、导致错误或妨碍使用的问题，再改善论证和表达。可在现有授权内查证、推导、调试或重写；修订须改善实际产物，不能用措辞掩盖缺证据、实现失败或不利结果。
4. **复核修订结果**：检查原问题是否消除，并核对修改牵连的内容。代码运行相关检查与必要测试；检索和分析回查来源、计算及对照；文稿检查主张、数字、图表、引用与修订要求的一致性。依据受影响范围复用仍有效的验证；最终再通读或检查完整交付，避免局部修好却整体失配。修改若造成退步，保留或恢复更好的版本。
5. **决定下一轮或交付**：尚有能在当前范围和预算内修复的实质问题就继续，不要求用户提醒“再检查一次”。完成条件满足、必要检查通过且没有已知未解决的关键缺陷时，交付当前最佳版本；轮数和自评分不作完成依据。

自评的依据尽量来自可复查的实际材料。自己换一个角色检查仍是自审，不能称为独立复核；未运行的测试、未核对的来源和主观认可不得写成已通过。迭代研究实现时保留探索与确认的区分，不能用反复试验挑选有利结果冒充独立验证。

同一问题反复未改善时，先诊断是否缺少证据、方法无效或检查标准不清，改用有依据的解法或更有区分力的验证，不机械重复同一轮。资源接近上限时优先处理关键缺口；达到上限或遇到真实阻塞后，交付已完成且可核验的部分，说明未达条件、影响和最小后续动作。调整目标、扩大投入或外部行动仍遵循原有授权，不能因追求满意而自行扩展。

简单答复可在一次检查后完成；复杂任务的有效迭代应体现为错误修复、证据补齐、论证改善或可用性提升。沿用现有文件与状态，不强制建立逐轮评分表或保存每份中间草稿；只在接续、复现或用户审阅需要时记录关键修订及验证。最终交付采用通过检查的版本，不把几个未完成版本交给用户自行拼装。

## 何时与用户交流

- **通常直接处理**：能从材料或检索查明的事实、授权范围内的局部方法探索、基线与分析选择、代码调试、图表和正文修改，以及正常阶段衔接。重要假设简要说明并允许用户纠正，不将其一律变成提问。
- **需要具体交流**：用户独有且无法推定的信息；会改变已确定研究目标或显著影响资源的取舍；必须由现场人员完成的动作；尚无授权的外部行动。先完成不依赖答案的准备，再给出自己的推荐、理由、备选及影响，只询问最小未决项。
- **提问后继续组织**：必要答案未到时不擅自代答；推进其他不受影响的工作。用户补充信息后主动判断其影响并接续，不要求用户再次布置任务。
- **持续可见**：进展更新说明新发现、当前决定和正在解决的瓶颈。用户中途询问状态或局部问题时先回答，再继续原任务，除非用户明确暂停或改变范围。

用户保留目标、重要取舍与最终提交决定；助手负责把需要决策的事项准备到可判断、可审阅。用户仅要求评估、记录或修改 skill 时，主动性体现在完成该范围，不扩展为启动具体课题。

## 从当前瓶颈切入

| 当前情况 | 优先执行 | 本轮完成条件示例 |
| --- | --- | --- |
| 只有领域兴趣 | 选择不同问题来源，查最近工作，比较研究价值与可验证性 | 有证据的主推方向与备选、最危险假设和最小验证 |
| 有想法但新意不清 | 查同问题异术语、邻近方法、简单替代，核对原文 | 明确实质差异、撞车风险和什么证据会改变判断 |
| 方案成立但实现不明 | 检查公开实现、许可、接口和资源；实现最小端到端路径 | 实际 smoke run、输入输出、运行记录与可处理故障 |
| 只有初步结果 | 检查测量、强基线、混杂与不确定性，运行最有区分力的对照 | 对继续/修订/停止有用的结果与决定 |
| 有可靠实验但没论文 | 提炼贡献，建立图表与主张映射，直接写正文 | 连贯章节或完整初稿，引用和缺口明确 |
| 稿件弱或临近截止 | 按目标要求识别拒稿级缺陷，聚焦关键证据与论证 | 已落实的必要修改和可审阅稿件 |
| 有评审意见 | 按真实意见映射证据、修改、补实验与回复 | 回复及对应稿件同步更新，未完成项如实标记 |

已有材料能回答的问题不要重复问。工具和权限允许时直接执行检索、推导、实现、分析与写作；不能把关键词、待办或实验设想冒充调研或实验结果。

## 最短的可信完成路径

持续推进时，在已有状态或提案里维护核心主张、已有证据、当前最大缺口与下一项可验收交付，并写清后者解除哪项实验或成稿依赖。结合 [顶刊顶会标准](顶刊顶会标准.md) 预判成功后的贡献价值；有限资源优先投入能决定贡献或完成论文的工作。

先按当前证据确定优先任务；阶段可以重叠，不是逐项审批关卡：

| 当前证据状态 | 优先任务 |
| --- | --- |
| 关键风险尚未排除 | 用低成本检验判断方向去留，排除足以使主要投入无效的已有工作、测量或资源问题 |
| 问题价值已有支持，关键解法尚未成立 | 主动构造和验证能形成贡献的机制，解决决定性技术障碍 |
| 核心证据已经具备 | 补齐投稿必需缺口，持续完成主稿、图表与附件 |

具体错误和新反证在任何阶段都及时处理；已解决的判断复用其证据，不在每个阶段重新跑全套查新与审计。在当前阶段内，再比较候选动作能否解除关键依赖、复用已有积累，以及算力、机时、现场劳动和等待成本是否值得其带来的判断或成稿进展。

对一次主要检索、实现、训练或采集，在已有状态中简记以下内容即可；普通小改不重复建表：

| 需要明确 | 记录内容 |
| --- | --- |
| 决策与依赖 | 要消除的未知；完成后可以继续哪项关键实验或稿件工作 |
| 最便宜的有效验证 | 可复用资产、必须新增的部分、实际可验收产物 |
| 投入与上限 | 预计时间/算力/费用、估算依据、已授权范围内的本次探索上限；用户操作与等待成本 |
| 结果与分支 | 有利、不利或无结论时分别继续什么、修复什么或停止哪条路线 |

区分实测耗时与假设外推，不虚构成功概率、精确收益分数或固定发表周期。预算未知时，先做现有授权覆盖的低成本检查或短运行以估算；高成本投入前解决真正影响资源的未决项，不要求用户为每个常规步骤新批预算。大规模训练前先证实相关的数据、指标与基线路径能运行；理论任务用推导或算例验证关键依赖，不强套训练流程。

判据来自领域意义、测量噪声和资源，不能临时为好结果修改。达到本次探索上限仍无结论时，交付实际证据，选择更便宜的判别、暂缓该路线或说明追加投入的理由；追加投入仍须在用户总预算内，无新依据时不反复上调同一路线的上限。局部路线停止不等于整体任务结束，继续其他已授权且必要的工作。检索足以支持当前决定就进入验证；新搜索由具体未知或时效变化触发。

等待训练、设备或用户输入期间，推进不依赖结果的问题设定、相关工作、方法、分析脚本、图表代码或补充材料。能独立推进的工作可交错安排，但不能挤占关键任务所需资源；结果段保留明确未完成状态，不为填满等待时间制造文档。

等待不等于暂停整个项目。只有所有剩余动作都依赖该外部条件，或继续工作会造成重复运行、证据污染、资源冲突或方向性误判时，才把阶段标为等待；否则先推进独立依赖，并在状态入口记录正在等待的具体条件。

## 检查跨轮实质进展

主要阶段检查时，与上一阶段对比：贡献判断是否被新证据推进、关键实现是否完成、必要证据是否补齐、主稿是否新增可审阅内容。直接引用已有决策、运行与稿件变化，沿用状态记录，不另建打分表，也不要求每轮都有正结果。

若这些方面均无实质变化，先区分真实长任务或外部等待、执行故障、低信息量试验与反复分析。依据原因修复关键路径、改用更有区分力的检验或推进不受阻的必要产物；不能只重新描述缺口、改名或增加文档。正常耗时和一次失败不自动触发换题。

可靠否定一条路线也算进展，但须明确停止或修订的范围、保留可复用成果，并在既定目标与授权内推荐和推进有依据的后续工作。若需改变用户确定的研究目标，先准备具体取舍再交流；不把“然后怎么办”直接退回用户。

## 稳定主线与进入定稿

核心贡献及关键验证获得支持后，在已有状态中暂定本稿范围和投稿必需项：每项对应主张、当前缺口与完成条件；其余作为可选增强。探索期允许调整假设，进入成稿期则优先完成已确定的必要证据与正文。

新增工作须说明它解决哪个关键反对意见、目标要求或已发现的有效性问题，以及不做会影响哪项结论。没有具体影响的扩展留作后续，不因“再多一个任务更好看”延后完整稿件。

已解决的判断复用其证据和适用条件；仅在新证据、具体错误、此前遗漏的关键反对意见或用户目标变化时重开，记录触发原因和受影响项，只重做必要部分。范围暂定不能阻止纠错，也不覆盖定稿前必要的时效核验。

当必要证据支持有意义的核心贡献、主要反对意见已处理或主张已合理收窄时，转入 [论文写作与投稿](论文写作与投稿.md) 的完整成稿与附件制作。若收窄后失去目标贡献，重新做贡献预判并建议调整；不能为赶进度删除实质问题后仍宣称满足原目标。

## 让主张对应证据

在已有研究材料中说明关键主张由哪些推导、对照、实际运行或文献支持，以及还缺什么。根据主张数量与材料复杂度选择文字、表格或引用，保持对应关系清楚、便于更新。

“已验证”须限定到具体条件和检验。新证据改变判断时，更新受影响的方法说明、图表和论文结论；贡献被否定时明确修订或撤回，保留原始实验与失败依据。

## 每次完成可审阅的一段工作

简要说明本轮要消除的缺口，然后执行到约定产物可审阅。实现与验证紧密相连：脚本要实际运行，图表要能追溯，文稿要写成段落；不可运行时明确停在设计/静态检查。

需要用户现场操作时，先交付：目的、已核对的前提、具体操作/命令、配置、输出与日志字段、成功和中止条件。只询问尚未知且无法安全推定的接口或资源；收到原始输出后由助手继续分析，不要求用户先整理结论。

如果任务因真实阻塞不能完成，说明阻塞影响哪项产物、已完成什么、恢复所需的最小输入；继续完成不受影响的部分。风险与目标未改变时，不在阶段之间反复问“是否继续”。用户明确只要建议、评审或记录时，按该范围交付。

## 阶段交付应有的内容

- **研究提案**：问题及重要性、最近工作实质区别、核心洞见、可能反例、最小验证、资源与有利/不利/含糊结果后的决策。
- **实验交付**：主张、对比条件、数据划分、指标和分析、命令与版本、运行状态、实际产物、偏差和下一决策。
- **稿件交付**：真实正文、图表、引用和必要附录；标清尚缺的证据，附可读/可编译状态。
- **返修交付**：评审原文对应的回复、证据、修改位置与完成状态，不能只有回复话术。

交付形式取决于任务用途与项目规模，可在已有材料中完善，也可按独立用途组织成品。研究推进与写作的具体衔接见 [论文写作与投稿](论文写作与投稿.md)。
